When to use it

Use the global build (peak.min.css) when Peak styles the whole page. Use the scoped build (peak.scoped.min.css) when other code shares the page and shouldn't be restyled: widgets, embeds, page-builder blocks from other vendors, an existing site you're moving to Peak part by part.

How it works

Every rule of Peak and Blades is wrapped in @scope (.peak) to (.peak-ignore): it matches inside a .peak element and stops at a .peak-ignore boundary.

  • Inputs work the same: set them on :root, .peak, [data-theme] or [data-peak-scope]. Their defaults are the only rules outside the scope.
  • Inherited properties (color, font) still flow into .peak-ignore, as CSS inheritance does; nothing else does.
  • .peak on <html> makes the whole page Peak, like the global build.
  • rem refers to <html>. On a nested .peak, the fluid root size is off, so text, headings and spacing stay in proportion to the page.

Browser support

@scope is in Chrome and Edge 118+, Safari 17.4+ and Firefox 146+. Older browsers ignore the whole scoped stylesheet; for a public site that must support them, use the global build.

In page builders

Peak's layout and component classes work on a page builder's container blocks too: put the class (peak-grid-auto, peak-card, peak-band…) in the block's class field. For Stacks 6, where each block sits in .out > .stacks_in wrappers whose unlayered CSS would override Peak, Peak includes targeted overrides for those wrappers, so grids, clusters, cards, bands and heroes lay out as on a plain page. Text blocks are spaced like paragraphs, also where Stacks 6 writes a text block's first paragraph without a <p>.
