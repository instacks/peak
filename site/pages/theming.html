Inputs and derived tokens

Peak has two kinds of custom properties:

  • Inputs such as --peak-hue, --peak-radius or --peak-type-ratio. Single values you set. Each has a default and a tested range; see the input reference.
  • Derived tokens such as --peak-primary, --peak-surface or --peak-h2. Computed from the inputs, for both color schemes at once. Read them in your own CSS; don't set them. See derived tokens.

Peak also sets Blades' --pico-* variables from its tokens, so everything Blades draws follows the inputs as well.

The whole page

:root { --peak-hue: 160; --peak-chroma: 0.12; --peak-radius: 0.75rem; --peak-font-family: Avenir, Montserrat, Corbel, sans-serif; }

Put this in your own stylesheet after Peak's; unlayered CSS always wins over Peak's layers.

One section

Inputs work on any element with data-peak-scope (or data-theme): Peak recomputes its derived tokens there, so the section gets a palette of its own.

Light and dark

Every Peak color is a light-dark() pair, so the scheme decides which half is used. By default the page follows the visitor's system setting (with <meta name="color-scheme" content="light dark">). Force a scheme with data-theme, on <html> or on any section:

data-theme="light"

Always light. A link.

data-theme="dark"

Always dark. A link.

A light/dark switch

A <select class="peak-scheme"> anywhere on the page switches it, with CSS only (:has()). The header of these docs has one.

CSS can't remember the choice on the next page. That's the one job of Peak's only script, peak-scheme.js (@instacks/peak/scheme): it saves the choice in localStorage, sets data-theme on <html> before the first paint, and keeps every switch on the page in sync. Load it in the <head>, without defer:

Deep fills in dark mode

In dark mode, primary and secondary buttons are light fills with dark text by default. Set --peak-dark-fills: 1 to keep the light scheme's deep fills with white text instead.

Exact colors

The derived palette covers most designs. When a brand guide prescribes exact colors, set the light and dark value of a surface or text color directly. Each pair replaces the derived color in that scheme; unset ones stay derived.

:root { --peak-bg-light: #fafaf7; --peak-bg-dark: #0e1113; --peak-heading-light: #1b1f24; --peak-heading-dark: #f4f1ea; }

Available for the page background, surfaces, text, headings, muted text, borders and the secondary fill (see Exact colors). These are outside the contrast guarantee: check them yourself.

Reading tokens in your CSS

Use the derived tokens for your own components, and they follow every input and both schemes:

.promo { padding: var(--peak-space-l); border-radius: var(--peak-radius); background: var(--peak-accent-subtle); color: var(--peak-text); box-shadow: var(--peak-shadow); } .promo strong { color: var(--peak-accent); } /* A lighter version of the brand color, still in both schemes */ .halo { background: oklch(from var(--peak-primary) l c h / 0.15); }

Blades and Pico variables

Peak writes Blades' --pico-* variables from its tokens on every theme root (:root, [data-theme], [data-peak-scope]). Setting a --pico-* variable yourself still works and wins, but it won't follow the inputs or the color scheme. Prefer the inputs, and use --pico-* only for what Peak has no input for.

/* Works, but fixed in both schemes */ :root { --pico-form-element-spacing-vertical: 0.5rem; }

Compact mode

Blades' data-compact attribute (on <html> or any element) gives denser forms and a flatter card look. Peak leaves it as Blades draws it.
