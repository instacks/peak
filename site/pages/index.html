What Peak is

Peak is a CSS-only layer for Blades CSS, a maintained fork of Pico CSS. Blades gives every HTML element a good default look; Peak keeps that and adds three things:

  • A token system. About sixty --peak-* inputs (a hue, a chroma, a radius, a type ratio…) generate every color, size and space. Lightness is pinned per color scheme, so any slider position keeps WCAG contrast. See Theming.
  • Layouts and components. Grids that need no breakpoints, sidebars, bands, heroes, cards, badges, chips, callouts, tabs, toasts, drawers, steps and more, all as .peak-* classes. See Layout and Components.
  • Whole pages. The examples show a landing page, an admin dashboard, a blog and a shop built with Peak's classes and a few inputs, nothing else.
  • Modern platform features. Native popovers with anchor positioning, <dialog> with entry and exit transitions, animated <details>, container queries, light-dark() and relative OKLCH colors. No JavaScript is needed for any component.

Principles

  • HTML first. An <article> is a card, a <details name> group is an exclusive accordion, a ul[popover] is a menu. Classes are for what HTML can't say.
  • Never fight the user. Peak lives in cascade layers after Blades. Your own unlayered CSS always wins, whatever its specificity. See Cascade layers.
  • Inputs are the API. The --peak-* custom properties are public and stable; renaming one is a breaking change. Everything else is internal.
  • Progressive enhancement. Anchor positioning, @starting-style and animated <details> are used where the browser has them. Without them, menus open centered and closing is instant, but everything works.
  • Respect preferences. Reduced motion, more contrast, reduced transparency, forced colors and print each get their own treatment.

Browser support

Chrome and Edge 123+, Firefox 128+, Safari 18+. Newer features (anchor positioning, ::details-content, interestfor, overlay) are progressive enhancements. The scoped build needs @scope: Chrome/Edge 118+, Safari 17.4+, Firefox 146+.

Relation to Blades and Pico

Peak imports Blades whole into @layer blades and never patches it. Everything Blades and Pico document still works: their classes (.container, .grid, .secondary, .outline…), attributes (aria-busy, aria-invalid, data-tooltip, role="switch") and --pico-* variables. Peak sets the --pico-* variables from its tokens, so prefer the --peak-* inputs; a --pico-* variable you set yourself still wins.
